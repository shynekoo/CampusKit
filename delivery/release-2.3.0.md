# 科信小助手 2.3.0

- 版本代码：158
- 安装包：`delivery/科信小助手-2.3.0.apk`（4.93 MB）
- sha256：`48b2955b10b4f46442a0e60c194f1e847d060b418882f66c7b3ee0927d21be4a`
- 包名不变（`io.qzxy.lite.preview`），可直接覆盖安装，数据保留
- 新增权限：`REQUEST_INSTALL_PACKAGES`（安装更新用）、一个不导出的 `ApkProvider`（把安装包交给系统安装器）

## 一、启动时检查更新

打开应用后约 1.2 秒（等课表先画完），在后台线程读一次版本清单。清单比本机新，就弹一页公告：标题是版本号，正文是这一版改了什么，底部两个按钮——「更新」和「稍后」。

- **点「更新」**：下载安装包，对话框里显示百分比与已下载/总大小，可取消。下载完成后先核对清单声明的字节数与 SHA-256，任何一项不符就删掉文件、提示失败，**不安装**。核对通过后交给系统安装器；如果系统还没允许「安装未知应用」，会说明原因并跳去那项设置，同意后回到应用自动接着装。
- **点「稍后」**：记住这个版本代码。同一版本在之后的启动里不再弹，装了更新的版本才会再问。
- **读不到清单**：没有网络、地址失效、清单被改坏，三种情况结果一样——什么都不显示。检查更新失败不是新闻，弹窗告诉用户才是打扰。
- **手动**：「账号」页底部那句版本号现在整行可点，右侧写着「检查更新」。手动查一定会给答复（有新版本 / 已是最新 / 查不到），因为这是用户主动问的。
- **放不下的内容**：说明最多八条，公告正文的高度上限是屏高的 52%，超出的部分滚动，两个按钮始终在屏幕上。
- **下过的包不会常驻**：启动检查时顺手删掉一天前的安装包。否则「下载了但没装」的那一份会一直占着约 5 MB。

清单长这样（`delivery/update/update.json`）：

```json
{
  "version": "2.3.0",
  "versionCode": 158,
  "notes": ["这一版改了什么", "一条一句"],
  "url": "https://…/campuskit-2.3.0.apk?sharecode=…",
  "bytes": 5170844,
  "sha256": "48b2955b…1be4a"
}
```

`bytes` 与 `sha256` 可省略；省了就不校验，但仍要求 HTTPS。

## 二、清单里的话一句都不信

清单是个放在公开地址上的普通文件，谁都能改，所以在 `core/UpdateManifest` 里逐项验：版本名要像版本（`2.3` 或 `2.3.0`）、版本代码是正整数、下载地址必须是 `https://` 且不含 `..`、说明 1–8 条且每条单行 160 字以内、sha256 是 64 位十六进制。任何一项不合格，整份清单作废，等同于读不到。

比较用的是**版本代码**，不是版本名：「2.10」按文本排在「2.9」前面，而系统本来就拒绝降级安装，只有整数能回答「这个比装着的那个新吗」。

JSON 解析器是手写的（约 120 行，在同一个文件里），只认对象、字符串、整数、字符串数组与 null，并且**拒绝**尾逗号、单引号键、注释、对象后面的多余内容——手写清单最容易出的就是这几种错，与其猜它想写什么，不如当它没写对。

## 四、清单托管在哪，代价是什么

用的是内置发布，清单和安装包都在同一个公开静态地址下：

- 清单：`https://wbapp-g8yy3klci8kmeufm6vdn0h.app.workbuddy.host/update.json?sharecode=BZD63HRP4B`
- 安装包：`…/campuskit-2.3.0.apk?sharecode=BZD63HRP4B`
- 不带 `?sharecode=` 会返回 403，所以地址里的这一段是必需的，不是多余的参数。
- 地址与 sharecode 写死在 `UpdateCheck.MANIFEST` 里。国内网络直连可用（这台机器实测：清单 200、安装包 200 且字节数一致）。

代价要说清楚：

1. **拿到链接的人都能下载**这个安装包。链接本身不算公开，但它不是密钥。
2. **平台若关停或换了 sharecode**，检测就失效。失效是安静的：应用当作「没有新版本」，其它功能不受影响，但从此不会再自己提示更新——那时只能靠手动发新包。
3. 静态服务不支持 Range，下载中断只能整个重下（现在就是这么做的：每次重新开始，并先清掉上一次的残留文件）。

## 五、以后怎么发新版

1. 改 `scripts/build_preview.py` 的 `FIELD_VERSION_NAME` 与 `client/android/AndroidManifest.xml` 的 `versionCode`（约定：清单里写目标版本代码 − 1，`--field-water` 构建会 +1）；
2. `python scripts/build_preview.py --field-water`；
3. 把新 APK 复制成 `delivery/update/campuskit-<版本>.apk`，用它真实的字节数与 sha256 更新 `delivery/update/update.json`（版本号、版本代码、说明、地址里的文件名）；
4. 重新发布同一目录（链接不变），发布后 `curl` 一遍清单和安装包，核对哈希；
5. 删掉目录里旧版本的 APK，避免越传越大。

注意顺序：**先出最终安装包，再写清单里的哈希**。任何一次重新构建都会改变哈希，先写清单后构建必然对不上，而对不上的结果是被静默拒绝安装。

## 六、验证

- 核心断言 1034 项通过，其中 38 条属于 `UpdateManifest`：正常清单、可省略字段、未知字段忽略、转义、以及 20 种应当被拒绝的写法（HTTP 地址、`file://`、含 `..`、缺字、版本代码为 0 或小数、空说明、9 条说明、负数大小、非 64 位哈希、尾逗号、未加引号的键、说明里带换行等）。
- 线上实测：清单返回 200 / 558 字节，解析出版本 2.3.0、代码 158、字节 5170844、哈希一致；安装包返回 200、5170844 字节、`application/vnd.android.package-archive`，下载后算出的 sha256 与清单完全相同。
- APK 内确认含 `UpdateCheck`、`ApkProvider`、`update.json` 与 authority 字符串；`aapt2 dump badging` 确认 `versionCode='158' versionName='2.3.0'`、`REQUEST_INSTALL_PACKAGES` 已声明；v2/v3 签名通过。
