# 科信小助手 2.3.8

版本码 167 · 2026-11-16

## 这一版只做一件事：把「为什么不能开」问出来

2.3.7 已经证明请求过了版本墙——`dev/mode/start` 回 `-3「设备当前状态下，无法操作」`，这是业务逻辑跑完之后的判断，不是版本协商退回的。但设备详情里看不出这句话具体指什么：

- `gene.status = 99`，官方文案映射是「锁定」，可水控机开机待用也可能是这个值，无法区分；
- `payItems` 是 `[{seq:100,type:91},{seq:90,type:21}]`，而官方 `PaymentType` 枚举只有 **商家钱包 91 / 余额 92 / 一卡通 93**——`type 21` 不在其中，含义不明；
- `wallet.total`、`ofCash`、`olCash` 全是 `0`，看起来像余额不足，但 `prepay` 是 `false`，后付费设备不该被余额挡住。

三种解释都能说通，靠猜已经试了四个版本。所以这一版不再改开启逻辑，只加一个**只读**的读取。

## 新增「读取设备状态（只读）」

设备详情 ⓘ → 诊断… → **读取设备状态（只读）**，一次取回三条官方接口的原始回答：

| 接口 | 回答什么 |
| --- | --- |
| `GET /api/v1/ui/app/dev/dev-use-way?did=` | 这台机器允许哪种使用方式（官方用它决定按钮与参数） |
| `GET /api/v1/ui/app/dev/status?did=&more=true` | 比详情更细的运行状态，用来解释 `gene.status=99` 到底算什么 |
| `GET /api/v1/bill/lst-owner` | 有没有未结账单压着 |

三条都是 GET，**不改设备状态**，也不需要站在机器旁边。结果弹窗可直接复制，字段里的 `token`/`uid`/手机号等在复制前就已剔除。

三条各自独立：某条失败只记下原因，不影响其它两条。
