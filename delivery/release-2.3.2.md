# 科信小助手 2.3.2

2026-11-16。慧生活登录页顶部加「支付宝一键登录」，手机号验证码原样留在下面。

## 为什么改

2.3.1 之后登录页会把服务端给的原因显示出来，那句是「请升级最新版应用」。核对下来不是版本号的问题：图形验证码与短信两条路径都还正常，登录这一步则多了一个用于支付宝授权的开放字段。慧生活新版登录页本身就带支付宝快捷登录，拿回授权码后走同一个登录入口，短信登录只是保留。

## 改了什么

**登录页**：同意条款下面就是「支付宝一键登录」，一整行蓝色按钮；再往下一条细线写着「或使用手机号验证码」，原来的手机号、图形验证码、短信码一个没删。

**授权流程**（`AlipayLogin`）：

1. 工作线程里调起支付宝授权页；
2. 解析回调结果，要求状态与结果码同时表明授权成功，取出授权码；
3. 把授权码作为登录凭据的一部分提交给慧生活，拿到账号标识与登录票据；
4. 走原来的 `LifeSessionVault` 加密保存，成功后的行为与短信登录完全一致。

失败按原因说话：用户取消 →「已取消支付宝授权」；SDK 抛错 →「没能唤起支付宝，请确认已安装并登录支付宝」；服务端拒绝 → 服务端原话。

**构建**：引入支付宝官方 SDK 15.8.42（Maven Central，SHA-256 固定）。项目没有 Gradle，AAR 手工合并：`classes.jar` 进 javac 与 d8；SDK 需要的 Activity、`org.apache.http.legacy` 与权限写进清单；SDK 的字符串资源单独生成，并用 `--extra-packages` 生成 SDK 自己的 `R`。详见 `client/THIRD_PARTY.md`。

APK 从 5.17 MB 涨到 5.34 MB。

## 必须说清楚的

- **授权身份属于慧生活**：这一步用的授权串是慧生活客户端自带的固定参数，其签名由慧生活自己的私钥生成。所以支付宝授权页显示的是「慧生活798」，不是「科信小助手」。这组参数随官方客户端分发，不是本项目的凭据，本项目也无法吊销它；登录页上已写明这一点。相关风险与处置登记在 `docs/security.md` 的 R1。
- **能否成功由支付宝决定**：SDK 会把调用方的包名与签名一并上报，支付宝若按授权身份绑定校验，本项目的签名会被拒。这一版把流程完整做出来了，但没有真机验证。
- **失败不会挡路**：授权失败只写一行状态，手机号表单仍在原位，可以立刻改走短信。
- **服务端那一关仍在**：即使拿到了授权码，登录仍可能被服务端拒绝。若如此，问题不在客户端。

## 验证

- 核心断言 1034 项通过（本次没有新增可离线测试的逻辑，`AlipayLogin` 依赖 Android SDK）；
- 构建通过；`aapt2` 读到 `versionCode=160 / 2.3.2`，清单里 SDK 的页面均已注册；
- APK 内确认含 `AlipayLogin`、`com/alipay/sdk/app/AuthTask` 与授权码字段；
- 线上清单 `2.3.2 / 160 / 5338780 bytes / sha256 ce458ce6…893db` 与下载回来的包逐字节一致；
- **支付宝授权、服务端兑换、登录成功这三步均未在真机上跑过**。

## 装不上或登录失败时

- 授权页没弹出来：确认手机装了支付宝并已登录；没有的话会走 SDK 的 H5 授权页。
- 支付宝里点了确认，回来显示授权未完成并带一串状态码：把那串数字发我，能定位是签名被拒、授权身份被限制还是网络问题。
- 显示服务端错误：说明这次授权没有被接受，需要记录请求发生的时间点。
