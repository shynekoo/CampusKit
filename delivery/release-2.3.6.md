# 科信小助手 2.3.6

2026-11-16。撤掉每点一次就白打七次请求的版本号阶梯，新增一个诊断入口。

## 背景

2.3.5 让控制请求改发对齐后的版本头，并留了一条保底阶梯：只要服务端还说「请升级」，就按序列往上试。实际用下来这条阶梯没有穿过门槛——每次点「开启用水」都会连打七次请求，全部被同一句话挡回。既然数值比较走不通，继续在客户端猜下去只是浪费请求。

## 这一版做了什么

**撤掉版本号阶梯**：现在只发一次，被挡就明说「这条控制接口要求官方新版协议，本应用暂时发不出来」，不再反复重试。

**新增「协议探测」**（设备详情 ⓘ → 诊断… → 协议探测）：把「猜」变成一次可执行的检查——按顺序尝试几种最可能的请求形态，把服务端对每一条的原话列出来，命中即停。**这个入口会真的向设备发一次开启请求**，界面上也照此标注为「会尝试开启一次」；它属于诊断功能，不是日常用法，正常用水不需要经过它。

> 后续说明：该入口的请求带有实际控制效果，已列为待整改项（见 `docs/known-issues.md`）；**自 2.6.1-beta.1 起已从发布包移除**（构建期断言保证），旧版本的入口仍然可用，请勿点击。

## 验证

- 核心断言 1034 项通过；fieldtest 断言改成锁新的判定（版本号常量、升级判定只认「升级」不认其它失败码）；
- `aapt2` 读到 `versionCode=165 / 2.3.6`；v2/v3 签名通过；
- APK 内确认含「协议探测」与 `LifeProtocolProbe`；
- 线上清单解析通过：`2.3.6 / 165 / 5338780 bytes / sha256 d0af9eec…dfea74f`。

## 装上之后

1. 扫码进用水页 → 右上角 ⓘ →「诊断…」→「协议探测（会尝试开启一次）」；
2. 弹窗会列出每一条尝试的结果，可「复制」；
3. 结果只用于判断服务端接受哪种请求形态，不改变本机的开启逻辑。
