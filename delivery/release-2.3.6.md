# 科信小助手 2.3.6

2026-11-16。官方 3.1.10 的包取回来了：`versionCode` 确实是 `31010`，但把它原样报上去，`/api/v1/dev/start` 还是那句「请升级最新版APP」。版本号理论到此为止，换一种问法。

## 包里看到了什么

`com.cloudora.android` / `versionCode=31010` / `versionName=3.1.10`，62 MB。反编译只出 30 个类——它是加固的：`classes.dex` 的头部（`string_ids_size=843`、`class_defs_size=30`）只描述一个几十 KB 的壳，真实的 70 MB 代码被壳藏在后面，dex 头被抹掉。试过 `dexdump`（头部自洽、其余 69.9 MB 无主）、按 `file_size` 自洽性反查真头（零命中）、zlib 解压（无）、应用宝/豌豆荚/apkpure/apkcombo/小米/酷安下载（无此应用或只到 3.1.7 / 超时）。**静态这条路到此为止。**

能从字符串表里捞出来的有用信息：

- 请求层是 `com.ilife.lib.coremodel.http.ApiClient`，里面有 `basicParamsInterceptor` 和 `okHttpClient`；
- 字符串表里还有 `AppSigningUtil`、`AuthVM$getSignKey`、`HmacSHA256`、`X-Sign` 这类痕迹；
- 接口清单 104 条，其中**有一条 3.1.5 没有的 `/api/v1/dev/mode/start`**，实测存在且鉴权在前（不带 token 回 `-99`），另外还有 `/api/v1/dev/receive`、`/api/v1/ui/app/dev/dev-use-way`；
- 官方包里**没有**「请升级最新版APP」这句，说明它是服务端下发的判断，不是客户端本地文案。

## 已经证伪的两个假设

1. **「版本号比服务端要求的小」**：2.3.5 的梯子从 31010 试到 50000 全被同一句挡回，2.3.6 又用官方正版 `31010` 复核一次，仍然被挡。数值比较不存在。
2. **「参数不全」**：`-1` 的 `msg` 在空 body 打登录接口时是「请求参数错误」，在这里是「请升级最新版APP」。同一码不同因，说明它在参数校验之前就按别的东西拦了。

## 这一版做了什么

**撤掉版本号阶梯**：它只是每点一次「开启用水」就白打 7 次请求。现在只发一次，直接被挡就明说「这条控制接口要求官方 3.1.10 的新协议，本应用暂时发不出来」，并指向探测入口。

**新增「协议探测」**（设备详情 ⓘ → 诊断… → 协议探测）：把「猜」变成一次可执行的实验，按顺序试 10 种请求长相，把每一条的**服务端原话**列出来：

| # | 试的东西 |
| --- | --- |
| 1 | 旧路径 + `ApplicationType: 1,1`（基线，已知会回「请升级」） |
| 2–3 | `ApplicationType` 换成 `1,2` / `2,1` |
| 4–6 | 分别加上 `VersionName: 3.1.10`、`App-Ver: 3.1.10`、`X-Api-Version: 3` |
| 7 | `User-Agent` 换成 `okhttp/4.12.0` |
| 8–9 | 换新路径 `/api/v1/dev/mode/start?did=&mode=&ptype=…`（带/不带 `args`） |
| 10 | 旧路径额外带 `mode` 参数 |

判据只有一条：**它不再说「升级」就算过墙**——那时哪怕回「参数错误」也是极有价值的结果（墙过了、参数不对），我们就知道该改哪里。命中即停，不会对设备连发多次；而且被墙挡回的请求根本没进业务逻辑，重试不会多开一次水。

## 验证

- 核心断言 1034 项通过；fieldtest 断言改成锁新的判据（`LifeVersion.CODE==31010`、`upgradeRequired` 只认「升级」不认 `-1`/`-99`/`code:0`）；
- `aapt2` 读到 `versionCode=165 / 2.3.6`；v2/v3 签名通过；
- APK 内确认含 `协议探测`、`mode/start`、`App-Ver`、`LifeProtocolProbe`；
- 线上清单用 `UpdateManifest.parse` 解析通过：`2.3.6 / 165 / 5338780 bytes / sha256 d0af9eec…dfea74f`。

## 装上之后

1. 扫码进用水页 → 右上角 ⓘ → **「诊断…」→「协议探测（会尝试开启一次）」**；
2. 弹窗会列出 10 行结果，点「复制」发我；
3. 我按结果决定：哪条过了墙就照那条改；如果全被同一句挡住，那就说明它要的是**请求签名**（新版本里那套 `AppSigningUtil` / `getSignKey`），那时唯一的办法是拿到服务端签发的签名密钥——这条我会直接说清楚，不会再让你反复试。
