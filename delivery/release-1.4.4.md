# CampusKit 1.4.4

2026-11-15。版本代码 139，`delivery/CampusKit-1.4.4.apk`，4,871,010 字节，
sha256 `e2b731fe5732ea35f25200bd14b4128c0515f3d2def7498a6d0eac5cdfdcbe91`。
签名密钥与 1.4.3 相同，可直接覆盖安装；课表、趣智登录状态、设置都保留。

这一版只解决一件事：**充值仍然下不了单**。你看到的报错是：

> 两条充值通道都没接受这笔订单。旧版钱包通道：错误码 8 登录失效,请重新登录；
> 支付宝直连通道：充值金额错误（错误码 157）。余额刚才是用同一个登录状态查出来的，
> 所以账号没有失效。

这两个码恰好指向两处不同的错误，而且都不是「账号掉登录」。

## 8 是怎么来的：通道选错了

原版 6.5.28 里 `MyApp.f` 写死为 `true`，`sj.y0.n(int)` 直接返回 `MyApp.f || i == 1`，
所以 `MyApp.e` 恒为 true；`ui.h.n()` 因此永远返回 `settlement/alipay/recharge/balance`，
`BaseNetActivity.A0()` 永远拼 `https://v3-api.china-qzxy.cn/`。`ProjectInfo.getIsMigrated()`
在 `migrateDTO` 缺失时还返回 1。**也就是说原版根本不走 `wallet/recharge/aliPay`。**

我们上一版把 `user/info` 里缺 `isMigrated` 当成 0，于是先打旧版钱包；
旧服务器不认 v3 的 loginCode，回了 8。余额是走 v3 查的，当然还是好的——
这正是你说的「同一个登录状态」。现在缺标志一律按 v3 处理，只有明确读到 `0` / `false`
才切旧版；旧版只保留为「v3 真的回了登录拒绝」时的兜底。业务拒绝（157 之类）
不再顺手去试旧版，也就不会再冒出那句误导人的「登录失效」。

## 157 是怎么来的：金额不是学校配置里的那个

对线上接口做了匿名探测（未登录，不产生订单）：

| 请求 | 结果 |
| --- | --- |
| `GET settlement/recharge/package/list?projectId=100` | `20.0 / 30.0 / 50.0 / 100.0 / 150.0` |
| 同上，未配置档位的学校 | `158 未配置充值金额` |
| `POST settlement/alipay/recharge/balance`（无登录态） | 无论金额填 1、50、300、1000、`50.00` 都是 `8 登录失效` |

最后一行说明：**8 在登录校验阶段就挡住了，157 只可能出现在登录通过之后的金额校验**。
而学校确实有一份服务端配置的充值金额表，157 与 158 是同一组金额校验的错误码。

原版从这张表里拿到的 `amount` 是 JSON 数字 `50.0`，Gson 交给客户端的就是字符串
`"50.0"`，`U2()` 把它原样放进 `rechargeMoney` 并参与签名。我们上一版写死了
`20 / 50 / 100 / 300` 四个整数，还把用户输入规范化成 `"50"`——
金额既可能不在该校档位里，拼写也和服务器配置的 `"50.0"` 不同。

## 改了什么

1. **充值页先拉学校自己的档位**：进页面时 GET `settlement/recharge/package/list`
   （旧版学校走 `wallet/recharge/package`），用返回的金额生成按钮，默认选中第一个；
   服务端没配档位（158）或网络失败时退回内置金额并明确提示，不会挡住余额显示。
2. **金额原文一直带到订单里**：`50.0` 不再被改写成 `50`，签名和正文用同一个字符串；
   自定义金额放宽到 `0.01–1000` 元、最多两位小数（探测里确实存在 `0.01` 的档位）。
   按钮上仍显示 `50 元`，下单时发的仍是 `50.0`。
3. **通道判定按原版来**：默认 v3，业务拒绝直接给出可操作提示：
   「服务器没有接受 ¥… 这个充值金额（错误码 157）。请回到充值页选学校配置里列出的
   金额……这笔订单没有创建，也没有扣款。」不再报「登录已失效」。
4. **签名拒答多给一次机会**：原来只在服务端消息里出现「签名」字样时才换另一种
   原生盐重试；现在任何业务拒绝都会试一次，避免签名问题被包装成别的错误码。
5. **清掉混进界面的对话用语**：报错里那句「把这句话发给我，我按错误码继续对」
   以及账号资料失败提示里的类似句子都删了，它们不该出现在 App 里。

## 验证到哪一步

- 核心断言 **823 项通过**（1.4.3 是 803；新增 20 项覆盖档位原文、小数金额、
  范围边界与「原文参与签名、改写成整数会改变摘要」）。
- 线上匿名探测确认了档位接口的数据形状、158 的含义，以及 8 与 157 的先后关系；
  **带真实登录态的下单仍无法通过匿名方式验证**——服务器会先要求登录。
- `aapt2` 读到 versionCode 139 / versionName 1.4.4，v2/v3 签名校验通过。
- **没做到的**：依然没有真机（adb 无设备、模拟器起不来），所以「装上去点一次
  能不能跳支付宝」没有实测。本版能保证的是：报出来的金额是学校自己配置的、
  拼写与原版一致、通道不再选错、157 的提示能直接照着改。
