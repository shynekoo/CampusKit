# 科信小助手 2.3.3

2026-11-16。修掉支付宝登录成功后一条永远刷不掉的假报错。

## 为什么改

用户装 2.3.2 后原话：

> 支付宝授权可以使用，但是登录后显示暂时无法确认登录状态，请刷新重试（-1），刷新也没用，这个是显示bug好像

判断是对的。支付宝那一步、凭据兑换、保存全都成功了——问题只在**登录之后那一次状态核验**。

## 原因

核验失败时服务端回的码被一律翻译成了「暂时无法确认登录状态，请刷新重试」，而服务端从来没有这么说过，刷新当然也没用。

把失败码区分开之后结论很清楚：服务端的「登录状态已过期」与「这次请求没问成」是两个不同的码。本项目把两者都当成过期处理，于是明明登录有效，界面却在要求刷新。另外，核验请求缺少账号参数时，服务端也会归到「请求没问成」这一类，而不是「过期」。

## 改了什么

**`LifeAuthApi`**

- 新增「过期」与「请求无效」两个常量及判定函数，把两种情况分开；
- 核验请求补上账号参数——服务端按账号定位凭据，只给票据时回的就是「请求没问成」。白名单同步收紧到这条路径，其它路径照旧拒绝。

**账号页（`AccountInfoActivity`）**

- 「过期」→ 清掉本机凭据，显示「登录已过期，请重新登录。」按钮变「重新登录」；
- 其余情况（含「请求没问成」）→ 显示「已登录」，不再出现那句读不懂、也刷不掉的提示。

**慧生活登录页**（底部的「检查登录状态」，那是个诊断入口）

- 「过期」→「服务器说登录已过期，请重新用支付宝授权或短信验证登录。」
- 其它负数 →「本机登录已保存。服务器这次没有返回可核对的状态，这不代表登录失效。」

## 必须说清楚的

- **补上的账号参数仍未在真机验证**：服务端在凭据不足时先回「过期」，走不到参数校验，只有带真实票据才能看到「请求没问成」。补参数是当时最合理的一步，能不能真的核验成功要装机才知道。
- **但显示已经不会错了**：非「过期」的失败只代表「这次没问成」，界面不再把它当成登录失效，所以即便参数仍不对，用户看到的仍然是正确的「已登录」。
- **只有服务端明确说过期才清凭据**：网络错误、解析失败一概保留本机登录。

## 验证

- 核心断言 1034 项通过（本版没有新增可离线测试的核心逻辑，核验逻辑依赖 Android 的网络栈）；
- 构建通过，`aapt2` 读到 `versionCode=161 / 2.3.3`，签名为 v2/v3；
- APK 内确认含新的状态判定与带账号参数的核验路径；
- 线上清单解析通过：`2.3.3 / 161 / 5338780 bytes / sha256 a4fc3dc4…450f64`；
- **带账号参数的核验能否返回成功未在真机验证**——装到手机上点一次登录页底部的「检查登录状态」即可判断。

## 装上之后怎么看

1. 用支付宝登录，回到账号页，应该只写「已登录」，不再有那句报错；
2. 想确认核验到底通没通：慧生活登录页底部「检查登录状态」——
   - 「服务器确认登录有效」→ 带账号参数的请求被接受了；
   - 「没有返回可核对的状态」→ 参数仍不对，但已经不影响使用。
