# 科信小助手 2.3.3

2026-11-16。修掉支付宝登录成功后一条永远刷不掉的假报错。

## 为什么改

用户装 2.3.2 后原话：

> 支付宝授权可以使用，但是登录后显示暂时无法确认登录状态，请刷新重试（-1），刷新也没用，这个是显示bug好像

判断是对的。支付宝那一步、`openCode` 兑换、凭据保存全都成功了——现在的问题只在**登录之后那一次状态核验**。

## 排查

`LifeAuthApi.verify()` 请求 `GET /api/v1/acc/stat`，把 `token` 放在 `Authorization` 头里，然后 `code>=0` 才算「已登录」。
现场拿到的是 `-1`，于是落进了「其它负数一律当成无法确认」的分支。直接打接口，把服务端的码对上：

| 请求 | 返回 |
| --- | --- |
| `GET /api/v1/acc/stat`（不带凭据） | `{"code":-99,"msg":"登录状态已过期"}` |
| `GET /api/v1/acc/stat` + 任意假 `Authorization` | `{"code":-99,"msg":"登录状态已过期"}` |
| `POST /api/v1/acc/login`，空 body | `{"code":-1,"msg":"请求参数错误"}` |
| `POST /api/v1/acc/login`，`openCode` 假值 | `{"code":-100,"msg":"系统错误"}` |
| `GET /api/v1/acc/logout` | `{"code":0}` |

`-1` 是这个服务端通用的「请求参数错误」，拿空 body 打登录接口也会得到同一个 -1。也就是说：

- **`-99` 才是「凭据过期」**，`-1` 只说明这次请求少给了参数；
- 服务端的判断顺序是先认凭据、再看参数——我们带着真 token 拿到 `-1`，恰好证明凭据是**被认了**的；
- 我们原来把所有负数都翻译成「暂时无法确认登录状态，请刷新重试」，而服务端从来没这么说过，刷新当然也没用。这正是用户看到的那句刷不掉的错。

顺带确认了 `/api/v1/acc/stat` 只认这一个路径（`/api/v1/acc/info`、`/acc/detail`、`/acc/balance` 等全部 404，而服务端对不存在的路径是标准 404 JSON），所以不是路径写错。

## 改了什么

**`LifeAuthApi`**

- 新增 `EXPIRED = -99`、`BAD_REQUEST = -1` 与 `expired(code)`，把「过期」和「请求没问成」分开；
- 核验请求改成 `GET /api/v1/acc/stat?uid=<uid>`（`statPath()`），账号参数一并带上——服务端按账号定位凭据，只给 `Authorization` 在真机上回的就是参数错误。白名单正则同步改为 `/api/v1/acc/stat(\?uid=[A-Za-z0-9_-]{1,128})?`，其它路径照旧拒绝。

**账号页（`AccountInfoActivity`）**

- `-99` → 清掉本机凭据，显示「登录已过期，请重新登录。」按钮变「重新登录」；
- 其余情况（含 `-1`）→ **显示「已登录」**，不再出现那句读不懂、也刷不掉的提示。

**慧生活登录页**（底部的「检查登录状态」，那是个诊断入口）

- `-99` →「服务器说登录已过期，请重新用支付宝授权或短信验证登录。」；
- 其它负数 →「本机登录已保存。服务器这次没有返回可核对的状态（-1），这不代表登录失效。」

## 必须说清楚的

- **`?uid=` 是个还没验证过的猜测**。服务端要的参数没法从外部探出来：凭据不对时它先回 `-99`，根本走不到参数校验，只有拿真 token 才能看到 `-1`。带上 uid 是手上最合理的一步，能不能真的核验成功要装机才知道。
- **但显示已经不会错了**：`-1` 只代表「这次没问成」，界面不再把它当成登录失效，所以即便 `?uid=` 没用，用户看到的仍然是正确的「已登录」。
- **`-99` 才会清凭据**：只有服务端明确说过期才动手，网络错误、解析失败一概保留本机登录。

## 验证

- 核心断言 1034 项通过（本版没有新增可离线测试的核心逻辑，`LifeAuthApi` 依赖 Android 的 `HttpURLConnection`）；
- 构建通过，`aapt2` 读到 `versionCode=161 / 2.3.3`，签名为 v2/v3；
- APK 内确认含 `statPath`、`expired`、`/api/v1/acc/stat?uid=`；
- 线上清单用 `UpdateManifest.parse` 解析通过，`2.3.3 / 161 / 5338780 bytes / sha256 a4fc3dc4…450f64`；
- **`?uid=` 能否让核验返回 `code>=0` 未在真机验证**——装到手机上点一次登录页底部的「检查登录状态」就知道。

## 装上之后怎么看

1. 用支付宝登录，回到账号页，应该只写「已登录」，不再有 `-1`；
2. 想确认核验到底通没通：慧生活登录页底部「检查登录状态」——
   - 「服务器确认登录有效」→ 带 uid 的请求被接受了；
   - 「没有返回可核对的状态（-1）」→ 参数还是不对，但已经不影响使用，需要的话下次抓一次官方客户端的请求再对。
