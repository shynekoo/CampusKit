# CampusKit 1.2.0

2026-11-15。版本代码 132，`delivery/CampusKit-1.2.0.apk`，
sha256 `f863a0e4de160a06eac568a663dbe1751c7c5bd196ba26f535fc4df12949a190`，4,850,530 字节。
签名密钥与 1.1.0 相同，可直接覆盖安装；课表、登录状态、设置、充值记录都保留。

## 1. 撤掉「平时分」

1.1.1 加的那个入口被去掉了，不是藏起来，是删掉：入口、菜单项、列识别、结果卡片、
页面关键词全部移除，APK 里搜不到「平时分」三个字。

原因是它查不到东西：学校的平时分不向学生端开放，菜单里没有入口，只能退到成绩页，
点进去看到的是总分——那个入口只会让人以为坏了。也不做本地估算冒充官方分数。

## 2. 成绩、空教室：改成一次点开就有结果

原来的做法是把学校网页塞进一个 WebView，让你自己在网页里点菜单、点查询，再点
「读取本页」，再解析表格。那不是查询功能，那是浏览器加截图。这一版整个换掉：

- **不再需要点网页**。点「成绩」或「空教室」，直接请求教务系统的查询接口，拿 JSON 渲染成原生界面。
- **空教室按你说的做**：周次 / 星期 / 节次 / 教学楼 / 场地类别 / 校区，点任意一项就换一次结果，
  下面直接列教室名、楼、座位数。默认落在**本周**、**今天**、按当前时间对应的节次。
- **成绩**：按学期列出课程、成绩、学分、绩点；学年/学期可切换，切换即刷新。
- 登录只在你需要时出现：没有会话时弹学校自己的登录页，登录成功自动返回并继续查询，
  密码输在学校页面里，应用不保存、看不到。

用到的接口（与学校「空闲教室查询」页面自己发的一致）：

| 用途 | 请求 |
| --- | --- |
| 当前学年学期、校区、场地类别 | `GET /cdjy/cdjy_cxKxcdlb.html?gnmkdm=N2155`（读页面里的 `xnm` `xqm` `xqh_id` `cdlb_id`） |
| 教学楼与节次时间 | `GET /cdjy/cdjy_cxXqjc.html?gnmkdm=N2155&xqh_id=&xnm=&xqm=` |
| 校历与可查周次 | `POST /cdjy/cdjy_cxQtlb.html?gnmkdm=N2155` |
| 空教室 | `POST /cdjy/cdjy_cxKxcdlb.html?gnmkdm=N2155&doType=query`（`zcd` 周次位掩码、`xqj` 星期、`jcd` 节次位掩码） |
| 成绩 | `POST /cjcx/cjcx_cxXsgrcj.html?gnmkdm=N305005&doType=query` |

学年、学期、校区、周次、节次时间全部在每次查询时从学校读，不写死在包里——九月换学期
不需要发新版本。协议参考了 [nuli936/kexin-rooms-android](https://github.com/nuli936/kexin-rooms-android)
（它的 `Protocol.java` 记录了同一套接口），登录仍走我们原来的 WebView，不引入账号密码存储。

网络层只允许访问 `jwglxxfwpt.hebeu.edu.cn` 的 `/cdjy/` 与 `/cjcx/` 这两组只读取路径，
不碰选课、不碰账号修改。原来的网页版留着当兜底：页面底部那行小字「用网页版打开」。

## 3. 充值：换掉跳转支付宝的那一步

原来是 `alipays://platformapi/startapp?appId=20000067&url=<订单串>`。这个地址的 `url`
参数要的是**网页地址**，而订单串是 APP 支付的 `app_id=…&biz_content=…&sign=…`，支付宝
打开后认不出来，所以表现为「跳不过去」。这是上一版写错了，不是你的操作问题。

现在改成支付宝客户端自己的支付服务 `com.eg.android.AlipayGphone.IAlixPay`——也就是官方
SDK `PayTask.payV2` 实际调用的那条通道：绑定服务、注册回调、把订单串原样交给支付宝、
由支付宝自己拉起收银台。付款结果按支付宝返回的 `resultStatus` 显示（9000 成功、6001 取消、
4000 失败……），余额仍然在返回后重新读取，不会自报「充值成功」。

**这一步没法在这里验证**：需要真手机、已安装支付宝、你的账号和一笔真实订单。另外这笔订单
是开给趣智校园官方 App 的 `app_id` 的，支付宝是否接受由另一个包发起，只能以实际返回为准。
如果支付宝回的是「订单参数错误」「商户参数错误」这类，说明官方这条通道不接受第三方包代发，
那就不是代码能修的了，我会把充值页改成明确引导回原版 App，而不是继续猜。

## 仍然存在的风险

1. 接口是老版本正方，学校改版会失效——失效时界面会写「学校没有返回…数据，页面可能改版了」，
   不会假装查到。
2. 空教室只反映教务排课占用，不保证现场没人临时用。
3. 成绩的字段名按正方标准（`kcmc`/`cj`/`xf`/`jd`）；如果你们学校改过名，会显示为空白，
   届时发我一行数据即可。
