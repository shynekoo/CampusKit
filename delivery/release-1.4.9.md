# CampusKit 1.4.9

2026-11-16。版本代码 144，`delivery/CampusKit-1.4.9.apk`，
sha256 `9661900476b2f7d06314dd4037fed9b490fea597d99ea877fbe8d16e48549e54`。
签名密钥与 1.4.8 相同，可直接覆盖安装；课表、趣智登录状态、慧生活/教务账号都保留。

这一版只做一件事：**慧生活798 扫码**。上一版放宽了「编号长什么样」，
但方向错了——新版设备码里根本没有设备编号。

## 真正的原因：码里是票据，不是编号

慧生活更新后，贴纸/设备屏上的码是这种：

```
https://i.ilife798.com/q/1/b?id=<一串票据>
https://i.ilife798.com/q/1/bm?/<一串票据>
```

`?id=` 后面那串东西**不是设备编号**，只是一张票据，必须拿去服务端换：

```
GET https://i.ilife798.com/api/v1/qr/use?id=<票据>
Authorization: <登录票据>
ApplicationType: 1,1

-> { "code":0, "data": { "qr": {"type":3}, "dev": {"id":"<设备编号>"} } }
```

1.4.8 把它当设备编号直接去查设备详情，服务端当然查不到；而更早的版本还会
因为「编号里必须含数字」直接把 `?id=a` 判成「不是设备码」。相机一直没问题，
是这一步把票据当成了编号。

## 按 GitHub 上同类项目的逻辑重写

两处参考（都是 MIT，且都在跟进线上服务）：

- [`ilife798/ilife798`](https://github.com/ilife798/ilife798) 的 `DeviceLinkParser`
  与 `QrScanResolve`——**扫码只负责拿到票据，换编号交给 `/qr/use`**；返回的
  `qr.type` 为 3（设备）或 8（门锁）才算可用。
- [`nocookies111/life-798`](https://github.com/nocookies111/life-798) 的
  `DeviceIdParser`——同一套 `?id=` 语义。

新的解析结果分两类，`Life798Qr.Scan` 里二选一：

| 码的样子 | 含义 | 之后怎么做 |
|---|---|---|
| `https://…/q/<n>/{b\|s\|billing\|vip\|wallet}?id=<票据>` | 票据 | 先 `GET /qr/use?id=` 换编号 |
| `https://…/q/<n>/bm?/<票据>` | 票据（保留 `bm?/` 原文） | 同上 |
| `https://…/q/<n>/<编号>` | 设备编号 | 直接查详情 |
| `ilife798s://i/device/{nav\|nfc}?id=<编号>` | 设备编号（NFC 标签） | 直接查详情 |
| 纯数字 / `did=` / `?q=` / `ilife://device/…` / JSON | 设备编号（旧贴纸） | 直接查详情 |

配套的三处修正：

1. **票据字符集放宽**：允许 `% + . / = ~ ? -`，最长 300。`bm?/` 那种票据本身带
   问号和斜杠，发请求前按 unreserved 规则百分号编码（`?` → `%3F`），与第三方
   客户端用 Ktor `parameter()` 发出的形式一致。
2. **不再要求编号含数字**，那是纯设备编号的规则，票据不适用。
3. **`/qr/use` 返回类型放宽到 3 和 8**，其余类型会在界面上写清「服务器返回类型 N」，
   不再笼统地说「不是受支持的用水设备码」。

设备页现在通过 `did` / `qrId` 两个不同的键接收：`did` 直接查，`qrId` 先换。
扫码页按解析结果选择，不再一律走一次兑换。

## 验证到哪一步

- 核心断言 **876 项通过**（1.4.8 是 864）。新增覆盖：五种 `?id=` 票据链接、
  `bm?/` 原文保留、`ilife798s://` NFC 深链、`/q/<n>/<编号>` 直连，以及
  `hello` / `about` / 多段路径等拒绝情形。
- 同一个解析器在 `client/build/core-tests` 里跑的是真实 JVM，不是模拟。
- `aapt2` 读到 versionCode 144 / versionName 1.4.9，v2/v3 签名校验通过。
- **没做到的**：仍无真机，带登录态的 `/qr/use` 无法离线验证。装上后请再扫一次；
  若仍失败，页面会显示「识别到的内容」原文和失败阶段（换编号 / 查详情），
  把那一行发我就能判断是票据没换到还是详情接口变了。

> 注：如果设备上贴的是微信/支付宝「小程序码」（圆形那种），任何二维码解码器都读不了，
> 只能走「手动输入设备编号」。这一版没有改变这一点。
