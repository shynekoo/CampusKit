# 科信小助手 2.3.4

2026-11-16。扫码进用水页后被自己挡住的那条记录，和一句没头没尾的「业务码 -1」。

## 用户看到的两屏

1. 扫码进「慧生活 · 用水」，设备名、位置都对，但没有「开启用水」，只有一行「设备已无使用者，请核实停水与账单后完成。」和一个「核实账单并完成」；
2. 再点一次刷新，按钮出来了，按下去是「服务器拒绝请求（业务码 -1）。操作记录已保留，请刷新核实，不会自动重发。」

两屏其实是同一件事的两头。

## 分析

**第二屏**：设备详情请求是成功的——名字、位置都显示出来了——所以凭据和设备标识都没问题，问题在这条开启请求的参数上。这一点没法从外部探出来：该路由先校验凭据再校验参数，没有有效票据只会被挡在第一步，只有装机才能看到「参数不对」这一层。参数表取自官方客户端，其中「随设备模式变化」的那个与付款方式那两个都可能是原因，本版不猜。

**第一屏**：2.3.2/2.3.3 在发请求**之前**就写下「待核实记录」，而那次请求被拒了、设备什么都没发生。记录留着不走，后果就是每次进页面都判定「上一笔还没有核实」，于是藏掉「开启用水」，逼你去核实一笔根本不存在的账单。**这不是服务器状态，是本机自己卡住了自己。**

## 改了什么

**撤销被拒的记录**（`LifeWaterRecord.discard`）：只有「服务器明确拒绝且原因明确指向参数未通过校验」才撤销——那时请求连业务逻辑都没走到，设备状态不可能变。其它失败码、超时、HTTP 错误一概保留记录，那正是记录存在的意义。撤销后弹一句提示并把页面刷新回正常状态，不再停在灰按钮上。

**失败信息带上服务端原话**：`LifeDeviceFailure.success` 现在把服务端给的说明一起接进去显示。同时新增 `Rejected` 子类，让上层能区分「明确拒绝」和「结果未知」。

**旧记录不再无路可走**：页面提示改成「上次开启没有完成：设备现在无人使用。确认没有产生账单后归档这条记录，就能重新开启。」按钮从「核实账单并完成」改成「核实并归档」——它本来就是那个动作，原来的字让人不敢按。

**诊断入口**：设备详情（右上角 ⓘ）多了「复制诊断信息」，把这台设备的原始返回、这次请求的路径和服务端原文复制到剪贴板。账号、票据、手机号、uid 一类字段在复制前就被剔除（`scrub`）。

## 验证

- 核心断言 1034 项通过；新增 fieldtest 断言：`discard` 之后记录为空、`Rejected` 带上业务码与服务端原话；
- 构建通过，`aapt2` 读到 `versionCode=162 / 2.3.4`；
- APK 内确认含 `复制诊断信息`、`记录已撤销`、`Rejected`；
- 线上清单解析通过：`2.3.4 / 162 / 5338780 bytes / sha256 ad03474e…b5557`；
- **`开启用水` 仍未成功**：本版只把页面解卡，参数问题的成因要等那份诊断信息。

## 装上之后按这个顺序做

1. 进用水页（扫码或从记录进入）。如果还显示「上次开启没有完成」，点「核实并归档」→ 弹窗确认 → 页面回到「设备已就绪」；
2. 点「开启用水」。若仍被拒，现在会自动撤销记录并给出原因，页面刷新回可再试的状态，不会再把页面锁死；
3. 点右上角 ⓘ →「复制诊断信息」，把复制到的内容发我。
