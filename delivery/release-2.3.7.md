# 科信小助手 2.3.7

版本码 166 · 2026-11-16

## 这一版解决什么

上一版让 app 自己去问「服务端到底要什么」，探测结果给了答案：**过墙的是 `dev/mode/start`**。

同一个账号、同一份凭据、同一个 `VersionCode: 31010`，两条路径的回复完全不同：

| 请求 | 回复 |
| --- | --- |
| `GET /api/v1/dev/start?did=…&upgrade=true&ptype=91&args=&rcp=false&cnt=1` | `{"code":-1,"msg":"请升级最新版APP"}` |
| `GET /api/v1/dev/mode/start?did=…&mode=0&ptype=91&args=&rcp=false&cnt=1&upgrade=true` | `{"code":-3,"msg":"设备当前状态下，无法操作"}` |

`-1「请升级最新版APP」`是版本协商在业务逻辑之前就把请求退回来了；`-3「设备当前状态下，无法操作」`是业务逻辑跑完之后给出的状态判断。**后者说明这条路径被接受了**，而且参数也过了校验——否则会回参数错误。

`dev/mode/start` 在官方 3.1.10 的字符串表里紧挨着 `dev/start` 和 `dev/end`，是 3.1.5 没有的新路径。

## 改了什么

- **开启用水改走 `dev/mode/start`**，参数顺序照抄被服务端接受的那一条；`mode` 取设备自己的 `gene.mode`，不自己编。若该字段越界（不在 0–999），拒绝发送，不拿猜出来的值去打设备。
- **`-3` 有专门的说法**：不再笼统地说「可以重试」（同样请求再点一次结果一样），而是写明「未下发任何指令：设备当前不接受开启，常见原因是账户余额为 0 或设备刚被他人占用」。
- **余额为 0 时提前提示**：设备就绪但 `wallet.total` 为 0，页面直接写「开启多半会被拒，请先在原版慧生活充值」。只是提示，不拦人——后付费、赠送额度、不同商户钱包的规则我们看不全，替服务端拦人可能挡掉本来能开的设备。
- 结束用水仍走 `dev/end`（3.1.5 就有，探测未发现新路径）。

## 需要注意

`-3` 究竟是余额为 0 还是别的状态，只有再点一次才知道。这次诊断信息里 `wallet.total` 是 `0`，所以余额是最可能的原因。若充值后仍回 `-3`，把页面提示和 ⓘ 里的诊断信息发我。
