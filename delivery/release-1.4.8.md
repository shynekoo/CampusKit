# CampusKit 1.4.8

2026-11-16。版本代码 143，`delivery/CampusKit-1.4.8.apk`，
sha256 `71f81ae8ca33733d8c0343be5910805e5cfc3ac04c5515e4054bcd450b639e10`。
签名密钥与 1.4.7 相同，可直接覆盖安装；课表、趣智登录状态、慧生活/教务账号都保留。

这一版两件事：**取消充值功能**，以及**修慧生活798 扫码**。

## 充值功能已移除

1.4.4 到 1.4.7 一直在修「订单能创建、支付宝收银台不弹」。到 1.4.7 已经把回调整到与官方
SDK 一致（`getVersion=4`）仍不弹，继续猜协议的成本已经高于收益——钱的事不能靠试。
所以这一版把充值整个删掉：

- 账户页的「充值」按钮去掉（趣智校园和慧生活都不再出现）。
- 删除 `RechargeActivity`、`RechargeApi`、`AlipayHandoff` 三个类，并在清单里注销页面。
  代码里不再有任何发起支付的路径，误触也不会有订单。
- **余额查询保留**，账户页照常显示余额。
- `RechargeSignature` 留在 core 里，只被测试引用（校验签名向量），没有任何网络能力。

需要充值时请用官方 App。这一条不是「暂时下线」，是移除。

## 慧生活798 扫码：放宽二维码识别

原来只认三种内容：纯数字、`i.ilife798.com/q/<数字>/<编号>`、`nfc.html?q=<编号>`。
这个白名单太窄——贴在设备上的码还见过 `?did=`、`/device/<编号>`、`/bind/...`、
`ilife://` 链接和带 JSON 的码，官方 App 能读，我们的会直接判「不支持」。

新规则参考了 GitHub 上的非官方客户端 [`nocookies111/life-798`](https://github.com/nocookies111/life-798)
（MIT）里的 `DeviceIdParser`，按优先级取编号：

1. 先找键：`did` / `deviceId` / `device_id` / `id` / `q`，支持 `=` 和 `:` 两种写法，
   支持 JSON（`{"deviceId":"..."}`）。
2. 再找路径：主机名以 `hnkzy.com` 结尾时取最后一段 8–32 位数字；否则看
   `device` / `devices` / `did` / `bind` / `binding` / `q` / `qr` 这些标记段后面的那一段。
3. 最后看是否整串就是一个编号（8–32 位纯数字，或带数字的 `A1B2C3D4` 这种编号）。
4. 都不满足才拒绝，且**拒绝时把扫到的原文显示出来**（截断 120 字），方便看出是
   陌生链接格式还是根本不是设备码。

另外加了**「手动输入设备编号」**按钮：识别不出来时直接输设备面板上的编号，
走同一个设备页，不再只能对着二维码反复试。
