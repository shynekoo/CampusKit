# CampusKit 1.1.0

2026-11-15。版本代码 130，安装包 `delivery/CampusKit-1.1.0.apk`，SHA-256
`e250fd9835e3f837c98ead8aaaf0f83fc31c45315e69f7aaace5b422a9b4d82e`。

本版新增三件事：趣智校园余额充值（支付宝）、教务成绩查询、教务空教室查询。

## 充值

入口：账号 → 趣智校园 → 充值。

实现依据是原版 6.5.28 的 `ui.recharge.RechargeActivity` 反编译结果：

| 环节 | 原版位置 | 本版做法 |
| --- | --- | --- |
| 路由选择 | `MyApp.e`（`ProjectInfo.isMigrated`）| 用 `project/info/triple` 读 `migrateDTO.isMigrated`，不猜 |
| 旧路由 | `wallet/recharge/aliPay` @ `wfwapi.china-qzxy.cn` | `RechargeApi` 白名单 |
| 新路由 | `settlement/alipay/recharge/balance` @ `v3-api.china-qzxy.cn` | 同上 |
| 请求体 | `payWay=2`、`rechargeMoney`、`signature` + 公共会话字段 | 按 `BaseNetActivity.t0(map,false)` 的字段集补齐 |
| 签名 | `sj.e0.e(map)`：排序拼接 + `JniUtils.getSk()` + MD5 | 当时由 `core.RechargeSignature` 实现，盐取自 `libklcxkjencry.so`；该类已于 2026-11-21 删除 |

签名盐的取值：原生 `getSk()` 依赖一个标志位，该标志位由 `checkSignature` 比对原版签名后置 1。
标志位决定它返回两个候选字符串中的哪一个，本版默认用「校验通过」那个；若服务器明确返回签名错误，
会再用另一个值重试一次——签名不通过时服务器不会建单，因此这次重试不会产生第二笔订单。
（两个盐值的原文已于 2026-11-21 的安全整改中从文档移除，源码侧随之删除，见 `docs/security.md`。）

**钱不在本应用里扣。** 流程是：服务端建单 → 把订单串交给支付宝
（`alipays://platformapi/startapp?appId=20000067&url=…`）→ 用户自己在支付宝确认付款 → 返回后重新
读取余额。任何一步失败都只显示失败原因，界面不会出现“充值成功”。

未实现：微信支付（订单绑定商户签名证书，第三方包名无法调用）、银联/招行/聚合/校园卡（各自需要 SDK）。
这些通道在充值页有明确说明，需回原版完成。

## 成绩查询与空教室

入口：今日 → 教务 → 成绩 / 空教室；课表 → 管理 → 查成绩 / 查空教室。

- 复用课表导入已有的 WebView 登录（`jwglxxfwpt.hebeu.edu.cn`，正方系统），应用不接触教务密码，
  登录状态由系统 Cookie 管理器保存，可随时“清除登录”。
- 不写死查询地址：先在页面里找菜单链接（`res/raw/edu_menu.js`，按文字匹配、排除 `javascript:`），
  找不到才退到已知的成绩页地址。学校改路由不会静默跳空页。
- 读取只取渲染后的表格文本（`res/raw/edu_tables.js`），上限 8 个表 / 400 行 / 24 列 / 单元格 120 字。
- 结果页（`EduResultActivity`）按内容渲染：能认出「课程 + 成绩」列的表格显示为成绩清单（右侧分数、
  下方学分/绩点），其余表格按原有列逐行显示，空教室因此保留校区/教室/节次的原始排布。
  列识别在 `core.EduTableColumns`，`学分` 永远不会被当成分数。

空教室的周次、星期、节次仍由用户在页面里选择，本版不代填表单——这些控件的结构没有真实页面可对照，
猜错会得到错误的空教室结果。
