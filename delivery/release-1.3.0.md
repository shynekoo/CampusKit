## 1. 教务账号存一次，之后自动登录

入口：成绩 / 空教室 页面上方 **「教务账号」**。

- 在里面填学号和密码，点「保存并登录」。保存时会**真的登一次学校系统**验证，密码错了当场提示，不会等到查成绩时才发现。
- 密码用 Android 密钥库（AES-256-GCM，密钥不可导出）加密，存在应用私有、不参与备份的目录里；卸载或点「清除已保存的账号」会连密钥一起删，残留文件也解不开。
- 保存之后，点「成绩」或「空教室」直接出结果：先查、发现没会话就用存好的账号自动登录、再查一次，整个过程不需要你操作。

## 2. 自动登录怎么做的

没有走浏览器，直接按学校页面自己的逻辑提交：

1. `GET /xtgl/login_slogin.html`，拿到 `csrftoken` 和表单里的全部隐藏字段（`language`、`xxdm`、`mm s f jm` 等）；
2. `GET /xtgl/login_getPublicKey.html?time=…`，拿到 base64 的 modulus（129 字节）和 exponent（`AQAB`）；
3. 用平台 RSA 做 `RSA/ECB/PKCS1Padding` 加密密码，再 base64 —— 和页面里 jsbn `RSAKey.encrypt` + `hex2b64` 的结果同一种格式；
4. 把 csrftoken 一起 POST 回 `login_slogin.html?time=…`，成功后把响应里的 Cookie 拿下来供后续接口使用。

这套协议先在 Python 里对着真实服务器验过一遍，再把同样的代码用桌面 JVM 打在真实服务器上跑了一遍：服务器返回的是
「用户名或密码不正确，请重新输入！」——说明令牌、公钥、加密串、字段名全部被接受，只差一组正确的密码。

## 3. 出错时说什么

| 情况 | 表现 |
| --- | --- |
| 密码错 | 「教务账号或密码不对，请修改后再试。」**不会重试**，避免把账号试到锁定 |
| 学校要验证码 | 「学校要求输入验证码，请改用网页登录一次。」并给出「网页登录」入口 |
| 域名解析失败 | 「连不上教务系统：域名解析失败，请检查网络（校外可能需要校园网或 VPN）。」 |
| 超时 | 「教务系统响应超时，请稍后重试。」 |
| 45 秒还没结果 | 进度条停下，写「读取超时」并给出重试 |

## 5. 风险与边界

- 学校改版登录页（字段名、公钥接口）会让自动登录失效，表现为「没有读到登录页的令牌」之类；此时用「网页登录」仍可用。
- 密码存在手机上是你选择的便利换来的代价：手机丢了、或系统被 root 后密钥被提取，账号就有风险。不想承担可以随时清除，改用网页登录。
- 只读：仍然只有空教室、成绩两组查询接口，没有选课、没有改密码。
