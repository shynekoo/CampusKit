# CampusKit 1.4.0

2026-11-15。版本代码 135，`delivery/CampusKit-1.4.0.apk`，4,862,818 字节，
sha256 `5612e1c886bda6f86aa367773c2a736caab3f86f08d9a1d03c7bbfc302485a9c`。
签名密钥与 1.3.0 相同，可直接覆盖安装；课表、趣智登录状态、设置都保留。

本版改的是四件小事，加上一条你没提但确实该改的：**教务系统的登录不再常驻**。

## 1. 空教室的默认值按你说的改

| 项 | 1.3.0 | 1.4.0 |
| --- | --- | --- |
| 场地类型 | 学校页面的默认项（不一定是什么） | **全部教室**（`cdlb_id` 留空，等于不限类型） |
| 校区 | 学校页面的默认校区 | **东校区(科信学院)**，按校区名含「科信」匹配，学校换排序也认得出 |
| 节次 | 只能选一对（1-2、3-4…） | **可多选**：勾第 1、2、5 节也可以，掩码按勾选的并集算（1,2,5 → `19`） |

节次改成多选后，标签会合并连续段（「第 1-2、5 节」），只有连续时才显示起止时间；
查询发的 `jcd` 是你真正勾的那几节，不会因为中间有空隙把没选的节次带上。

顺带把结果列表里的类型改成显示**教室自己的类型**（不过滤时），因为默认是「全部教室」，
原来那行会变成空的。

## 2. 登录只在查询时存在，离开页面就退

你担心的没错：1.3.0 是登录一次就把会话一直留在内存里，只要应用没被杀掉，学校那边
就一直是「在线」。这一版按「临时登录」处理：

- 进「成绩」或「空教室」→ 用存好的账号登一次 → 查 → 显示。
- **离开这个页面（返回、切到别的界面、按 Home）就调用 `/xtgl/logout.html` 退出**，
  同时把本地的 Cookie 丢掉。下次进来再登一次。
- 页面上多了一个**「退出登录」**：想立刻退出就点它，不用等离开页面。
- 会话**从不写盘**，只有密码那份密文存在密钥库里加密的文件里。

两个细节是为了不误伤：

- 从这两个页面点进「教务账号」或「网页登录」时不算离开，不会先把会话退掉再让你重登。
- 退出请求带着「当时那个会话」的标识；如果你很快回到页面并已经重新登录，迟到的退出
  任务会跳过，不会把新会话也一起踢掉。

代价是每次查要多花一次登录的往返（一般一秒左右）。换来的是：手机借人、丢在桌上、
后台放一晚，学校那边都不会挂着一个登录着的会话。

## 3. 密码被学校拒过一次，就不再自动重试

1.3.0 每次进页面都会拿存好的密码试一次。如果密码真的错了，你点几次就试几次——
正方这类系统连续失败会锁账号。现在把「被拒」记在偏好里（不加密，只是个布尔值）：

- 被拒后，下次进来**不会**再自动试，直接提示去改密码。
- 你在「教务账号」里重新保存（并验证通过）才会清掉这个标记。

## 4. 成绩报「教务系统暂时无法响应」的排查与加固

这条提示原来的全文是「教务系统暂时无法响应（HTTP xxx）」，说明是学校返回了 4xx/5xx，
不是登录问题（空教室能查，登录本身是通的）。看不到具体状态码，所以这一版做了三件事：

1. **不再写死成绩页地址**：登录后先读学校自己的菜单页 `/xtgl/index_initMenu.html`，
   按链接文字含「成绩」找出真正的成绩模块地址（含它自己的 `gnmkdm` 功能号），
   再拿这个地址去读学期、发查询。学校换了模块路径或功能号也不用改代码；
   菜单读不到时才退回原来写死的 `/cjcx/cjcx_cxXsgrcj.html?gnmkdm=N305005`。
2. **POST 被拒就换 GET 再试一次**：少数部署对表单 POST 返回 400/500，但同样的参数放在
   URL 上能正常返回。参数完全一样，只是换了传法。
3. **错误里带出真实状态码和学校原话**：现在会显示成
   `教务系统返回 HTTP 500（/cjcx/xxx.html）：<学校返回的前 90 个字>`，
   带路径、带状态码、带学校自己的报错文字。把这一行发我，就能定位到底是路由不对、
   功能号不对，还是查询参数缺字段。

参考来源对过：同一学校的 [nuli936/kexin-rooms-android](https://github.com/nuli936/kexin-rooms-android)
只覆盖空教室，没有成绩接口，所以成绩这块没有现成的接口定义可参照，只能按正方系统的通用形态做兼容 + 用错误回执校正。
